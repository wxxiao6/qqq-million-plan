# 列表外基金持仓（第一阶段）

用户可输入六位代码，添加当前天天基金数据源支持的人民币场外、按单位净值计价的基金。第一阶段包含已有份额和成本的持仓，不扩展列表外基金的历史申购补录或定投。不支持美元份额、场内 ETF、货币基金和手动估值。

## 录入流程

1. 搜索现有基金，或输入代码点击「查询基金」。
2. 本地已有资料时复用资料；未收录时从天天基金获取名称、类型、管理公司。核对响应代码，排除不支持的计价方式和币种。
3. 获取最新已公布净值和最近三个净值日，展示名称、分类、净值和日期。重复选择在 30 分钟内复用已成功获取的缓存。
4. 填写份额、总成本、成本单价中的任意两项，保存个人持仓。非纳指基金由服务器归类为 `fund`，不会默认计入纳指。
5. 暂时无法获取净值时，仍可保存已经核实身份的基金；估值为空而不是零。页面支持重试，后台同步恢复后重新估值。

## 数据结构与迁移

- `funds`：通用基金资料，独立于 `nasdaq_funds` 雷达目录。现有目录导入此表；雷达新增/更新通过触发器更新资料，雷达移除不删除个人基金及净值历史。
- `positions`：增加 `fund` 敞口，保留旧记录所有字段、用户归属、索引、账号归属触发器及自增 ID 水位。
- `fund_nav_history`：关联 `funds`，保留原有历史净值。
- `fund_nav_sync`：逐基金记录请求时间、成功时间、净值日期和错误。过时的请求结果不能覆盖较新的同步状态。
- `nav_sync_funds`：雷达成员、有效持仓、有效定投涉及的基金的去重并集。仅查询但未持有的基金不进入长期同步。
- `nav_snapshots`：持仓估值使用的净值。保留原有手动校正保护；首次持仓可直接复用已获取的公共历史。

本地 SQLite 与云端 D1 复用相同净值写入和基金查询 SQL。迁移文件：`db/migrations/045_personal_fund_catalog.sql`。执行云端迁移后再部署使用此结构的代码。本次本地开发不自动部署或修改线上数据库。

## 持续同步与补抓

- `/api/market/refresh`（本地）及 `/api/jobs/refresh`（云端机器任务）使用同一去重同步范围。
- 不再因为当天已成功运行而跳过后续净值更新或当天新增持仓。
- 复用 `scripts/cloud-jobs.mjs` 的已有周期调用，按北京时间 22 点首抓、23 点补抓、次日 08–11 点窗口内补抓一次；各窗口成功后去重，失败时下次周期调用重试。此脚本依赖已有调度器周期执行，本次不安装新的系统服务。
- 本地使用时录入立即查询，Next.js 本地服务在线期间通过现有 instrumentation 启动进程内任务，每 15 分钟检查上述时窗；成功状态持久化，失败重试，数据库租约避免多个进程重复执行。服务关闭期间不运行，重新启动且处于时窗时补抓。不安装新的系统服务。
- QDII 是否更新以数据源返回的净值日期为准，获取成功不等于当天净值已公布；延迟公布可在后续窗口补齐。

## 展示与验证

持仓页支持全部基金、纳指基金、其他基金筛选。公共雷达只读其原目录，不受个人添加影响。部分持仓缺净值时，总览使用「已估值资产」名称并提示未估值笔数；收益缺失保留为空。净值抓取失败保留最近已公布数据，显示更新暂缓并可单独重试。

验证涵盖：旧财务字段和用户归属迁移、有效/无效代码及不支持基金校验、首次净值失败仍可保存、缓存复用、同日恢复、新增基金参与后续本地及 D1 分页同步、重复持仓保护、手动净值保护、补抓窗口去重。浏览器验证通过真实列表外代码查询，仅获取公共基金数据，不在真实账本写入演示持仓。
