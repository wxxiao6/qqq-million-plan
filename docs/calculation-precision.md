# 基金计算与小数规则

## 适用范围与依据

本项目是个人持仓和定投记账工具。平台实际确认的金额、份额及基金公司公布的净值优先于本项目的计算估计。分红、复权、汇率、平台成本调整及净值发布时间也可能影响对账，不能仅靠改变小数位数消除全部差异。

官方规则并不完全一致：[汇添富申购说明](https://www.99fund.com/service/help_detail/10183446.html)规定净申购金额和份额四舍五入保留两位；[招商基金公开说明](https://www.cmfchina.com/web/noticedetails/204410/)中的份额规则为保留两位并舍去余数。因此，不将一种基金的份额舍入方式当成全市场统一标准。

## 计算与存储边界

- TypeScript 中使用 decimal.js 独立构造器，内部保留 40 位有效数字，默认 ROUND_HALF_UP：正负数的半数均向绝对值较大方向舍入，避免 Math.round 的负数差异及二进制浮点尾差。
- 人民币金额（总成本、扣款、手续费、已结算金额）到分，即两位小数。显式录入的扣款和手续费超过两位时提示用户核对，不默默改变扣款金额。持仓由单价和份额计算出的成本在入账边界舍入到分；CSV 成本使用同一口径。
- 定投累计投入在数据库更新时先转换成整数分再加减，避免连续小额扣款产生累加尾差；定投页面、额度统计也使用同一金额汇总函数。
- 手工录入或平台确认的份额保留原始精度，不强行压成两位。仅有总成本与单价时推导的份额最多保留八位，这属于反算持仓，不等同于登记机构确认份额。
- 净值和市场价格保留数据源提供的有效小数，不在采集时统一截为四位。展示至少四位；来源有更多位则继续显示。
- 持仓成本单价通过成本除以份额计算，内部不先截成四位。编辑回填的自动推导单价最多八位，录入预览显示八位，列表可按显示空间展示四位。未修改金额字段时（包括仅改备注或切换录入方式），保存原始成本和份额；只有用户实际修改金额字段后才按所选两项重新计算。用户输入的单价不在输入时强制截位，显示后的单价不反写成本和份额。
- 手续费外扣法：净申购金额＝扣款总额 ÷（1＋费率），费用四舍五入到分，入账本金＝实际扣款－已舍入费用，保持金额守恒。
- 自动记账份额当前沿用既有人民币场外基金默认口径：净申购金额 ÷ T 日净值，四舍五入两位。十进制函数提供显式截位模式，但尚未建立逐基金合同规则表；自动计算不能替代登记机构的实际确认。特殊舍入基金应按平台实际份额核对，不能宣称已经覆盖所有基金合同。
- D1 的批量自动确认改用扣款分整数与净值八位定点整数进行逐位长除，最后按余数四舍五入，避免 `ROUND(2.01/2,2)` 得到 1.00 的浮点边界问题；保留批内原子更新。超出支持精度或安全范围的自动记录保留待确认，本地使用同样的范围检查。D1 组合快照通过整数分块乘法按账户计算到分，再汇总；八位定点覆盖当前场外基金的份额和净值精度。金额和份额写入仍采用现有 REAL 字段，不迁移或批量改写历史账本。应用端十进制运算与 SQL 边界通过本地/D1 对照用例验证。

## 市值、收益与汇总

逐笔估值、净值差等中间结果保留精度。同一基金、同一购买账户的明细先汇总，再将市值、成本及当日收益舍入到分；持有收益为该账户市值减对应已估值成本。基金卡片加总账户金额，总览加总基金卡片，避免不同层级各自重新计算导致的分差。

缺净值的资产继续显示缺失，不冒充零市值；待确认资金与已确认资产分开。单日收益缺前值时仍显示缺失。

展示收益率保留两位百分数小数，舍入到零的金额和收益率统一展示零，不显示 +0.00、-0.00 或负零。金额展示到分不意味着净值、份额和所有中间结果都提前舍入。

## 回归样例

019441：市值 1805.71、总收益 -94.29，反推总成本 1900.00；份额 1008.23，对应单价 1.884490642…，八位显示 1.88449064。重新以该八位单价和份额计算成本，入账仍为 1900.00。

边界用例覆盖正负 1.005、2.675、净值五位以上、确认份额额外精度、1 万笔 0.01 元累计、账户/基金/总览逐级金额一致。

## 历史账本检查

`pnpm ledger:audit --db data/ledger.sqlite --out-dir data/backups/precision-audit` 使用只读连接和一致读事务检查实际本地账本。报告包括分以下金额、纯浮点尾差、扣款守恒、自动估算份额对照、计划累计对照、净值缓存一致性，以及不同舍入层级产生的统计差额。

该工具不读取密码、账号邮箱、会话令牌或备注，不支持修改账本。报告应放在忽略的 `data/backups/` 中，避免把财务明细提交到代码仓库。线上查询应只执行脚本 `--print-sql` 提供的 SELECT 语句，并将查询结果交给 `--input`；解析器会拒绝不完整结果或报告了数据写入的查询结果。

历史快照包含多位小数不等于交易数据错误，不能用当前持仓重建过去的真实组合。手工记录含分以下成本时，报告中的两位候选值仅供核对，不能据此恢复真实平台成本。手工确认的高精度份额也不能批量压成两位。清理历史账本前，应保留备份并逐项核实来源。
