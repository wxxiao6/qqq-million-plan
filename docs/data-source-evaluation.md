# 数据源方案评估

更新时间：2026-10-28（北京时间）

本文评估当前纳斯达克基金净值同步使用的必盈 API，以及参考 `TiantianFundApi` 项目后直接调用天天基金/东方财富移动端接口的可行性。测试只读取本项目的 `config/nasdaq-funds.json`，没有把参考项目复制或安装到本项目中。

## 结论

在 2026-10-28 晚间（用户观察时点约 21:55）测试，天天基金的 `FundVPageDiagram` 接口比当前必盈结果更新：88 只基金中 86 只返回了 2026-10-27 的正式净值和日涨跌；同一批基金在本地数据库中的必盈记录有 86 只仍停留在 2026-10-26。019738 和 019739 两个数据源都没有返回可用净值，不能通过更换接口解决。

净值数据源已确定为天天基金/东方财富接口，并已通过独立适配器接入。额度和费率复用天天基金接口写入 `agency` 维度；直销与代销继续分开建模，外部机器人写入的 `direct` 数据不受影响。

建议采用双数据源的“最新有效日期优先”策略：

1. 每日任务先调用天天基金 `FundVPageDiagram`，满足当日可用性和时效性。
2. 必盈保留为有证书的第二数据源，用于补缺、交叉校验和后续接口变更时的回退。
3. 对每只基金选择日期更新且字段完整的结果，并把 `source`、原始 URL、抓取时间写入净值历史表。
4. 对 019738、019739 继续保留上一次有效值，记录本次“无可用净值”，不要写入伪造的 0 值。

当前实现已经切换净值和代销额度同步优先级；必盈适配器仍保留为可替换的备用来源，基金概况任务暂时继续使用必盈。

## 一、必盈 API

### 文档和当前调用

- [必盈 API 文档中心](https://www.biyingapi.com/doc-center)
- [必盈基金接口文档](https://www.biyingapi.com/doc_jj)
- 当前净值接口：`GET https://api.biyingapi.com/jj/lsjz/{基金代码}/{BIYING_LICENCE}`
- 当前项目适配器：[src/server/market/biying.ts](../src/server/market/biying.ts)
- 认证配置：`.env` 中的 `BIYING_LICENCE`

必盈文档中心说明，免费证书每日可调用 100 次，日线数据在收盘后 30 分钟内更新完成。本项目有 88 只基金，单次全量同步会消耗 88 次调用，只剩约 12 次给失败重试和补采集使用。

### 优点

- 有明确的证书、文档和基金数据接口，接入方式清晰。
- 返回结构适合服务端保存，当前项目已经完成鉴权、并发、逐只失败隔离、幂等写入和任务记录。
- 可作为第二来源验证天天基金结果，减少单一数据源故障的影响。

### 缺点

- 本次实际观察到的时效不满足 21:55 获取上一交易日数据的要求：本地必盈记录中 86 只基金最新为 2026-10-26。
- 付费计划之外的免费额度很紧张，88 只全量同步后重试空间小。
- 019738、019739 返回的最近净值日不完整，当前无法形成可用最新记录。
- 数据更新时间受供应商处理链路控制，应用端无法自行缩短延迟。

### 优点

- 本次真实测试的时效明显更好，86 只基金拿到了上一交易日 2026-10-27 的数据。
- 不需要本项目的必盈证书，调用成本和每日证书额度压力较低。

### 缺点和风险

- 这是天天基金/东方财富移动端使用的接口，参考项目文档提供了调用方式，但没有看到面向本项目的正式 SLA 或稳定性承诺。
- 请求依赖移动端参数和请求头，接口字段、域名、风控策略可能变化，需要保留适配器和失败监控。
- `fundMNHisNetList` 已出现“网络繁忙”，说明同一数据源的不同入口稳定性不一致；不能把单个接口成功视为整个供应商永久稳定。
- 019738、019739 同样没有返回可用序列，说明这两个基金本身的数据状态需要单独核实。
- 使用前应确认天天基金/东方财富的服务条款、访问频率和缓存要求；建议并发限制为 4，并对 429、5xx 和空序列做退避重试。

## 三、限购额度和费率接口

参考项目没有封装完整的交易规则接口，但天天基金移动端还有一个可直接调用的接口：

```http
GET https://fundmobapi.eastmoney.com/FundMApi/FundRateInfo.ashx
```

请求参数可以使用：

```text
FCODE=基金代码
deviceid=1
plat=Android
product=EFund
version=6.5.5
```

### 字段能力

| 业务数据 | 字段 | 结论 |
| --- | --- | --- |
| 申购状态 | `SGZT` | 支持：开放申购、限大额、暂停申购、场内交易、封闭期等 |
| 单日申购上限 | `MAXSG` | 支持；纯数字字符串，空值表示没有数值上限或不适用于场内交易等状态 |
| 最低申购金额 | `MINSG` | 支持 |
| 申购费阶梯 | `sg[]` | 支持，包含金额区间、`source` 原费率、`rate` 天天基金优惠费率 |
| 赎回费阶梯 | `sh[]` | 支持，包含持有期限和费率 |
| 管理费 | `MGREXP` | 支持，年费率 |
| 托管费 | `TRUSTEXP` | 支持，年费率 |
| 销售服务费 | `SALESEXP` | 支持，但部分场内 ETF 返回空值或 `--` |

### 直销和代销的边界

这个接口的 `source` 和 `rate` 是同一份天天基金交易页中的“原费率”和“天天基金优惠费率”。因此，`rate` 可以作为**天天基金代销渠道的实际优惠申购费率**使用。它没有直销机构或其他销售平台的费率字段，因此不能代表基金公司直销费率，也不能代表其他代销平台费率。

因此业务上应分别保存：

- `direct`：基金公司直销页面或基金公司公告确认的申购费率、限额和状态；
- `agency`：使用天天基金返回的 `rate` 作为天天基金代销申购费率，同时保留 `source` 原费率、`MAXSG` 和 `SGZT`，并记录平台为天天基金。

基金公司直销费率仍需从对应基金公司直销页面、招募说明书或限购公告取得。天天基金 F10 页面可以看到“天天基金优惠费率”和日累计申购限额，但它是 HTML 页面，不是结构化 API；例如 `https://fundf10.eastmoney.com/jjfl_001092.html`。

管理费、托管费和销售服务费属于基金运作费用，按年费率从基金资产中每日计提；天天基金页面明确说明，公告净值已经扣除这些费用，投资者不会在每笔交易时另外支付。

### 不适合作为额度主接口的路由

`FundValuationDetail` 主要返回盘中估值。对本项目抽测的纳斯达克场外基金返回 `data: null`，不能作为限购额度或手续费来源。`FundNetList.ashx` 能返回 `SGZT` 和 `BUY` 等概览状态，但不返回 `MAXSG` 和完整费率阶梯，适合做列表概览，不适合作为交易规则主数据源。

## 四、建议的落地顺序

### 第一阶段：先做适配器和观测

增加独立的 `tiantian` 净值适配器，只负责读取 `FundVPageDiagram` 并返回统一结构：

```text
code, navDate, nav, dailyChangePct, sourceUrl, fetchedAt
```

保留现有必盈适配器。两个适配器都写入 `fund_nav_history`，通过唯一键 `code + navDate + source` 幂等更新，并在 `fund_ingestion_runs` 中记录每个来源的成功、失败、空序列和最新日期分布。

### 第二阶段：选择最新有效结果

对每只基金按以下规则选取本次当前值：

1. 过滤日期、单位净值和日涨跌格式不完整的结果。
2. 选择 `navDate` 最新的结果。
3. 日期相同且数值冲突时，保留两份历史并标记校验异常，暂不静默覆盖。
4. 两个来源都没有新数据时，保留数据库最后一次有效值，并显示数据日期和失败原因。

这样可以解决必盈延迟时页面仍停留在旧日期的问题，同时保留必盈的可追溯性。

### 第三阶段：设置验收和告警

每日任务完成后至少检查：

- 成功数是否达到目录总数的预期比例；
- 最新净值日期是否达到上一个交易日；
- 是否出现空序列、日期倒退或单位净值为 0；
- 两个来源在同一日期的数值差异；
- 019738、019739 是否恢复可用数据。

若天天基金接口连续失败，自动回退到必盈；若必盈仍滞后，则页面明确显示实际数据日期，不把旧值伪装成当日值。
