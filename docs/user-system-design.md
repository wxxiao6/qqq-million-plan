# 用户系统技术设计

更新日期：2026-11-04。本文描述当前源码；本轮修复尚未部署，生产状态需按实际发布记录核验。旧迁移与部署记录见 [历史实施记录](history/user-system-2026-10-30.md)。

## 当前范围与权限

- 仅一个本人管理员账号，不开放多人注册或邀请。
- 持仓与定投页面要求登录；访客访问时返回 `/quota`。
- 持仓及定投 Server Actions 在执行业务校验和数据库写入前调用 `requireUser()`。失效或缺失会话拒绝操作，不能仅靠页面跳转保护写入。
- 雷达、公开行情和手工市场刷新保持公开；定时任务与额度上报使用独立机器凭证。
- 定投只记账，不向销售渠道发起真实申购或扣款。

## 身份与会话

账号密码使用 PBKDF2-SHA256 哈希，服务端随机会话令牌仅以 SHA-256 摘要写入数据库。会话 Cookie 使用 HttpOnly、SameSite=Lax，HTTPS 环境使用 Secure。退出撤销服务端会话；登录限流按来源地址和账号组合执行。

首次使用在 `/login` 创建唯一管理员；已有账号后拒绝再次创建。SQLite 事务和 D1 原子批次中再次检查账号数量，防止并发创建第二个账号。初始化将历史未归属持仓、定投和快照认领给管理员，后续账本通过触发器自动归属。

## 数据边界

基金目录、额度和净值是共享数据；持仓、计划、执行记录和组合快照是个人账本。当前业务查询按单账号模型运行，并未实现完整的多用户 SQL 隔离。`users` 表和 `user_id` 字段存在不代表可安全开放多人。

代理保留来源检查及 `private, no-store` 响应策略；来源检查不能代替业务入口的身份校验。机器凭证不作为浏览器用户会话。

## 本地与云端

本地 SQLite 启动时按顺序执行迁移；Cloudflare 使用 D1。生产迁移和备份需独立执行，代码回滚不能替代数据库恢复。不要删除历史迁移或把线上数据库导出提交到 Git。

历史记录记载生产管理员曾完成初始化和账本归属；本文不据此断言当前生产状态，也不再将历史待办列为当前待办。生产验收应检查对应部署版本、匿名拒绝、登录后读写及机器任务。

## 验证要求

定投创建、编辑、执行、暂停、恢复、结束、删除及修正均需覆盖无有效会话时不调用写入服务；本地和 D1 分支分别验证。已登录的原有补录、回滚、并发和金额规则仍须通过。

未来多用户查询隔离及迁移要求见 [扩展计划](user-system-implementation.md)。
