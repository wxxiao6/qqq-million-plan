# 用户系统技术设计

日期：2026-10-30  
状态：本人单账号首版代码已实现并完成本地试用；生产 Worker 与 D1 迁移已部署，首次账号初始化待完成。详细分阶段方案及剩余生产步骤见[实施计划与技术方案](user-system-implementation.md)。

## 已确认范围

- 仅本人登录，不开放注册或邀请。使用账号和密码登录。
- 首次账号创建时，现有 `positions`、`dca_plans` 和 `portfolio_snapshots` 的未归属数据全部迁给本人账号。
- 持仓管理和定投管理页面要求登录；未登录访问时返回纳指雷达。持仓 Server Actions 保留身份校验；基金行情、额度读取和手工市场刷新保持公开可用。
- 定投仍只产生记账记录。后台定时任务与额度上报继续使用自己的机器凭证。

## 身份和会话

`users` 保存邮箱、密码哈希及账号角色。密码使用 PBKDF2-SHA256 哈希，服务端生成随机会话令牌，数据库只存令牌的 SHA-256 摘要。登录会话放在 HttpOnly、SameSite=Lax Cookie 中，生产环境启用 Secure；退出会删除服务器端会话。登录失败按来源地址和邮箱组合，在 15 分钟内限制到 10 次。

首次使用时，仅填写账号和密码即可创建唯一管理员账号，并认领已有账本数据。已有任意账号后，创建接口拒绝再次注册；SQLite 事务和 D1 原子批次内仍检查账号数量，阻止并发请求创建第二个账号。

## 数据归属

迁移为持仓、定投计划及组合快照增加 `user_id` 外键和索引。创建管理员时，单个 SQLite 事务或 D1 原子批次会创建账号并将现有空归属记录回填给该账号。数据库触发器将此后新增账本行自动标记为唯一管理员。由于当前产品明确只允许一个账号，业务 SQL 暂由服务端会话守卫限制入口；若以后开放多人，必须先把读写、关联、汇总、导入和后台对账逐项改为查询级用户过滤，再允许创建第二个账号。

基金目录、额度及净值快照是共享数据；持仓、定投执行记录和组合市值快照是个人账本数据。未登录访问持仓或定投页面时返回 `/quota`，持仓业务写操作拒绝未认证请求。页面顶部只保留品牌与账号入口，登录后的下拉菜单统一提供纳指雷达、我的持仓和我的定投，并标记当前页面；访客通过登录入口进入 `/login`。代理继续检查跨来源写入并为页面响应设置 `private, no-store`。

## 本地启用

本地 SQLite 会在应用启动时依序执行迁移。访问 `/login`，选择“首次使用？创建个人账号”，填写账号和至少 6 个字符的密码即可创建账号并自动登录。项目 `.env` 不应提交到版本控制。
